# 跨语言多仓库对照评测报告

评测日期：2026-08-01。

## 最终结论

正式对照覆盖 3 个公开仓库、3 种语言、15 条真实历史 Issue：Cobra（Go）、Vitest
（TypeScript）和 bat（Rust）各 5 条。每条任务都使用关闭 PR 第一父提交对应的独立
pre-fix worktree；RepoOps Agent 与 Claude Code 使用同一个 `deepseek-v4-pro` 主模型、
同一任务、同一人工标签和相同 commit SHA。

| 指标 | RepoOps Agent v4 | Claude Code v1 |
|---|---:|---:|
| Structured Success | **15/15（100.0%）** | 13/15（86.7%） |
| Classification Accuracy（全量） | **100.0%** | 86.7% |
| File Recall@5（全量） | **93.1%** | 77.1% |
| 调查工具调用 | **137** | 220 |
| 平均工具步骤 | **9.13** | 14.67 |
| Invalid Call Rate | **0.73%** | 5.45% |
| Evidence Completeness | 98.0% | **100.0%** |
| Hallucinated Citation Rate | **0%** | 4.46% |
| Runner-reported Total Tokens | **1,881,777** | 2,424,549 |
| 平均单题耗时 | **125.8 秒** | 137.8 秒 |
| 中位单题耗时 | **110.9 秒** | 118.4 秒 |
| 最大单题耗时 | **269.9 秒** | 381.5 秒 |

相对 Claude Code，RepoOps 的结构化成功率和分类准确率高 13.3 个百分点，File
Recall@5 高 16.0 个百分点；调查调用少 37.7%，runner-reported tokens 少 22.4%，
累计逐题耗时少 8.7%。15 条 RepoOps 输出全部可评分，因此本轮不再需要用“仅成功
样本指标”解释失败样本。

这说明在本轮固定协议下，RepoOps 的领域工具、检索约束和结构化收尾比通用
Bash/Read 调查面更稳定、更节制。它不等于 RepoOps 在所有仓库和语言上全面胜过
Claude Code：样本只有 15 条、每仓 5 条、只有一次模型采样。

## 分语言结果

| 语言 / 仓库 | Agent | 成功 | 分类 | File Recall@5 | 调用 | Tokens | 平均耗时 |
|---|---|---:|---:|---:|---:|---:|---:|
| Go / Cobra | RepoOps v4 | **5/5** | **100%** | **100%** | **43** | 647,920 | 166.1s |
| Go / Cobra | Claude | 3/5 | 60% | 60% | 83 | **590,191** | **164.6s** |
| TypeScript / Vitest | RepoOps v4 | 5/5 | 100% | **96%** | **47** | **643,542** | **107.5s** |
| TypeScript / Vitest | Claude | 5/5 | 100% | 88% | 81 | 1,389,224 | 153.8s |
| Rust / bat | RepoOps v4 | 5/5 | 100% | 83.3% | **47** | 590,315 | 103.7s |
| Rust / bat | Claude | 5/5 | 100% | 83.3% | 56 | **445,134** | **94.9s** |

收益并不均匀：RepoOps 在 Go 上修复了旧 v3 的结构化失败并达到 5/5，但耗时和 token
不优于 Claude；TypeScript 的文件召回、调用、token 和耗时均更好；Rust 的成功率与
文件召回相同，Claude 的 token 和耗时更低。总体优势主要来自 Go 的可靠性与
TypeScript 的检索效率。

## 数据与标签

每条任务满足：

1. 来源是公开仓库真实 Issue，并关联一个已合并、关闭它的 PR；
2. `expected_category` 根据 Issue 类型、标题和标签人工确定；
3. `relevant_files` 从关闭 PR 的核心生产文件中筛选，不把测试、锁文件和 Changelog
   机械纳入；
4. 标准答案不进入 Agent prompt；
5. 每条任务使用对应合并 PR 第一父提交作为 pre-fix 快照，15 条使用 15 个不同
   commit。

任务分布为 10 条 bug、5 条 feature。File Recall@5 衡量前 5 个预测文件对人工核心
文件的覆盖率，不等价于完整根因正确率。

## 公平对照协议

| 项目 | RepoOps Agent | Claude Code |
|---|---|---|
| 主模型 | `deepseek-v4-pro` | `deepseek-v4-pro` |
| 任务与标签 | 同一 15 条 | 同一 15 条 |
| 代码快照 | 每题独立 pre-fix commit | 相同 SHA 的独立 worktree |
| 调查工具 | pinned file read + 本地混合检索 + task state | Read + 只读 Bash/rg |
| 输出 | 相同 BenchmarkAnswer 字段 | 同字段 + CLI JSON Schema |
| 会话 | 每题独立 session/state | `--bare --no-session-persistence` |
| 超时 | 每题 600 秒 | 每题 600 秒 |
| 失败处理 | 不人工补答案 | 相同 |

两边各使用 2 个并发 case。并发只缩短墙钟时间，每题仍有独立上下文和 worktree。
Claude Code 的系统提示、工具协议与输出实现无法和 RepoOps 完全相同，所以这是“同一
主模型下的两个 Agent 系统”对照，不是只改变单一变量的模型实验。

## v4 做了什么优化

v4 针对 v3 的一条 Provider 参数解析失败、候选文件重复和搜索结果覆盖不足做了以下
工程修复：

- Provider 对短暂流式解析失败进行有限重试，并恢复可识别的 DSML 序列化工具参数；
- workspace 检索先按唯一路径聚合，再保留稀有查询词覆盖，减少同一文件不同 chunk
  挤占 top-k；
- 工具始终返回有效 JSON，搜索结果在输出预算内保留完整 top-k；
- benchmark prompt 明确 Issue 分类边界和受限工具词表；
- 对同一文件的重复精确读取增加节流，避免平移窗口消耗调用预算。

相关实现和回归测试位于 `nanobot/providers/base.py`、
`nanobot/repoops/retrieval.py`、`nanobot/agent/tools/repoops.py`、
`nanobot/repoops/benchmark.py` 与对应 `tests/`。

## 无效 run 与压力实验

为了避免只保留“最好看”的数字，以下结果仍保留审计，但明确排除在正式结论外：

- `deepseek-v4-pro-cross-language-repoops-unpinned-invalid/`：远程精确读取可能落到
  post-fix `HEAD`；
- `deepseek-v4-pro-cross-language-repoops-pinned-state-contaminated-invalid/`：虽钉住
  SHA，但复用了旧 task state；
- `deepseek-v4-pro-repoops-v6/`：单仓紧凑收尾压力实验不完整；
- `deepseek-v4-pro-repoops-v7/`：按用户要求中止，20 条中仅 18 条产生 shard 汇总，
  其中 15 条结构化成功、3 条因 endpoint 收尾连接失败而无答案，不能计算正式全量
  指标。

Python v5 虽达到 20/20 结构化成功，但在 GitHub Issue API 被网络策略拦截时，旧 prompt
没有携带已有 Issue 标题，分类与检索发生漂移，最终只有 70.0% 分类和 73.7% File
Recall@5。后续把标题直接放入 benchmark prompt，并明确 bug/feature 边界；针对 v5
的 6 条分类错误做隔离回归均得到正确分类。该 6/6 只证明目标缺陷已回归，不与正式
15 条跨语言全量指标混算。

## 复现

```bash
export REPOOPS_DEEPSEEK_AUTH_TOKEN='...'
export REPOOPS_GITHUB_TOKEN='...'

uv run python -m nanobot.repoops.cross_language_benchmark \
  --tasks eval/cross_language_tasks.json \
  --agent repoops \
  --config eval/deepseek_cross_language_config.example.json \
  --repository-cache /tmp/repoops-crosslang/sources \
  --worktree-root /tmp/repoops-crosslang/worktrees-repoops-v4 \
  --output-dir eval/runs/deepseek-v4-pro-cross-language-repoops-v4 \
  --jobs 2

uv run python -m nanobot.repoops.cross_language_report \
  --tasks eval/cross_language_tasks.json \
  --repoops-run-dir eval/runs/deepseek-v4-pro-cross-language-repoops-v4 \
  --claude-run-dir eval/runs/deepseek-v4-pro-cross-language-claude-code-v1 \
  --output eval/runs/deepseek-v4-pro-cross-language-comparison-v2.json
```

Claude Code 的具体无交互参数和轨迹采集方式见
[Claude Code 对照测试方法](Claude-Code对照测试方法.md)。
