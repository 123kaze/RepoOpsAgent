# RepoOps 真实历史任务集

本目录把“模型输入”“人工标准答案”“Agent 运行结果”分开保存，避免把人工检索
伪装成 Agent 能力。

## 数据

- `eval/repoops_tasks.json`：20 个来自 `HKUDS/nanobot` 的真实历史 Issue。
- `eval/demo_cases.json`：3 个 Issue、3 个 PR、3 个失败 CI run 的面试演示集。
- `eval/demo_ground_truth.json`：演示集的人工标签，**不会**进入 Agent prompt。
- `eval/cross_language_tasks.json`：Cobra、Vitest、bat 共 15 条真实历史 Issue，包含
  每题独立的 closing PR 与 pre-fix commit。
- `eval/deepseek_config.example.json`：只引用环境变量的 DeepSeek V4 Pro 配置。
- `eval/deepseek_anthropic_config.example.json`：与本机 Claude Code 对照使用的
  DeepSeek Anthropic-compatible 配置，只引用环境变量。
- `eval/deepseek_cross_language_config.example.json`：允许三个跨语言仓库、只引用环境
  变量的正式评测配置。
- `eval/deepseek_optimized_config.example.json`：Python 优化/压力回归使用的有界上下文
  配置，只引用环境变量。
- `eval/deepseek_demo_config.example.json`：CI 演示使用 8k 单轮输出、12 轮上限，并把
  runtime 内联结果阈值设为 18k；RepoOps 工具自身仍受 16k 输出硬上限约束。
- `eval/runs/`：实跑后生成的轨迹、预测和指标；每次运行使用独立子目录。

所有 20 个 Issue 都链接到一个合并 PR。`relevant_files` 只保留人工判断最接近
根因/需求入口的生产文件，不把所有改动文件机械地当作相关文件。首版标签主要按合并
PR 时点准备；后续审计发现部分 `nanobot/cli/commands.py` 在统一固定快照中已迁移到
`cli/gateway_runtime.py`、`cli/agent.py` 或 `command/builtin.py`。为保持旧基线
可比，本轮没有事后改标签；File Recall 的这个限制必须与原始分数一起披露。快照固定
为：

```text
repository: HKUDS/nanobot
commit: 6a1a45d07a6de420ba87c419ae30fcb4af76d4d0
```

## 运行协议

1. 检出上述 commit，并把它作为 Agent workspace。
2. 使用 OpenAI-compatible 配置时设置 `DEEPSEEK_API_KEY`；使用 Anthropic-compatible
   对照配置时设置 `REPOOPS_DEEPSEEK_AUTH_TOKEN`。GitHub 凭据分别为
   `GITHUB_TOKEN` 或 `REPOOPS_GITHUB_TOKEN`。
3. 配置只注册 `repoops_*` 工具；runner 还会在运行时移除其他工具。模型若尝试
   不存在的通用工具，该失败调用仍保留在 trajectory 并计入 Invalid Call Rate。
4. 每个 case 使用独立、ephemeral session。
5. 轨迹仅记录模型可观察的工具名、参数、状态、工具结果和最终答案，不保存隐藏
   reasoning；参数按敏感键名脱敏，工具输出、错误和最终答案另按常见 API key、
   GitHub token 与 Bearer credential 格式脱敏。
6. 人工标签只在运行结束后用于评分。

跨语言任务不能直接交给单 workspace harness，因为 15 条任务有 15 个 commit。
`nanobot.repoops.cross_language_benchmark` 会缓存三个仓库，为每题创建 detached
pre-fix worktree，再调用同一 RepoOps/Claude harness。RepoOps 的精确远程文件读取
由 runner 配置硬钉到任务 SHA；模型即使传 `HEAD` 也不会覆盖。

```bash
export DEEPSEEK_API_KEY='...'
export GITHUB_TOKEN='...'

uv run python -m nanobot.repoops.benchmark \
  --tasks eval/repoops_tasks.json \
  --config eval/deepseek_config.example.json \
  --workspace /absolute/path/to/nanobot-snapshot \
  --output-dir eval/runs/deepseek-v4-pro-baseline
```

Python 历史 RepoOps v3：

```bash
export REPOOPS_DEEPSEEK_AUTH_TOKEN='...'
export REPOOPS_GITHUB_TOKEN='...'

uv run python -m nanobot.repoops.benchmark \
  --tasks eval/repoops_tasks.json \
  --config eval/deepseek_anthropic_config.example.json \
  --workspace /absolute/path/to/nanobot-snapshot \
  --output-dir eval/runs/deepseek-v4-pro-repoops-v3
```

Claude Code 对照：

```bash
uv run python -m nanobot.repoops.claude_benchmark \
  --tasks eval/repoops_tasks.json \
  --workspace /absolute/path/to/nanobot-snapshot \
  --settings ~/.claude/settings.json \
  --model deepseek-v4-pro \
  --effort max \
  --output-dir eval/runs/deepseek-v4-pro-claude-code-v1
```

跨语言 RepoOps：

```bash
uv run python -m nanobot.repoops.cross_language_benchmark \
  --tasks eval/cross_language_tasks.json \
  --agent repoops \
  --config eval/deepseek_cross_language_config.example.json \
  --repository-cache /tmp/repoops-crosslang/sources \
  --worktree-root /tmp/repoops-crosslang/worktrees-repoops \
  --output-dir eval/runs/deepseek-v4-pro-cross-language-repoops-v4 \
  --jobs 2
```

把 `--agent` 改为 `claude-code`，并传入 `--settings ~/.claude/settings.json
--model deepseek-v4-pro --effort max`，即可生成同任务 Claude Code 对照。

演示集：

```bash
uv run python -m nanobot.repoops.benchmark \
  --cases eval/demo_cases.json \
  --config eval/deepseek_demo_config.example.json \
  --workspace /absolute/path/to/nanobot-snapshot \
  --output-dir eval/runs/deepseek-v4-pro-demo
```

`run_summary.json` 汇总模型、token usage、耗时和失败；`trajectories/*.json`
保存逐工具轨迹。Issue 基线额外生成 `predictions.json` 与 `metrics.json`。

## 指标边界

- 分类准确率与 File Recall@5 使用合并 PR 的人工标签。
- 工具 precision/recall 使用工作流要求的最小工具集合。
- citation 只有在引用 ID 存在，且 source 与 excerpt 能在工具结果中找到时才算
  有效；它是保守的字符串可追溯检查，不等同于语义事实核验。
- 全部评测现覆盖 4 个仓库和 4 种主要语言，但跨语言集每仓只有 5 条；多数配置只有
  一次全量采样，RepoOps 的一次重复 run 又出现 5 条收尾失败，仍不足以证明跨规模
  生产泛化能力或稳定 SLA。
- 统一 post-fix 快照与部分 PR 文件标签存在路径漂移；详见
  [对照报告](RepoOps与Claude-Code对照评测报告.md)。
